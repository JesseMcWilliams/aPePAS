# aPePAS: User Docs Backlog

> **Stage: Planning.** Add one line per user-visible change when it's made. At the end of the project, `User_Docs/` is written from this list instead of re-reading the project history. Once an entry is covered in `User_Docs/`, delete it.

| Date | Change | User doc / section it affects |
|---|---|---|
| 2026-09-25 | `Tests\Run-Tests.ps1` now requires Pester 6.0 or later (was 5.0). Its banner and the driver header say "aPePAS" instead of "Idira Unified Scripts". | User-Guide requirements / running tests |
| 2026-09-25 | On PowerShell 7, API errors now report their real HTTP status (a 404 used to show as a failed connection and force a needless re-login). Export All now shows a failed sub-report as Failed with its error, re-checks the login once before stopping on a 401, and in automation mode exits 2 (not 0) when any sub-report fails. Export All no longer runs List Reports, and runs the Master Policy snapshot on Self-Hosted only. | User-Guide Export All and automation exit codes |
| 2026-10-06 | Add Application Authentication Method supports `certificateattr` (certificate attributes). New optional CSV columns `Subject`, `Issuer` and `SubjectAlternativeName` take semicolon-separated `Attribute=value` pairs, listed in the same order as in the certificate (CyberArk requires this and doesn't report a wrong order); at least one is needed, and `AuthValue` is no longer a required CSV column (it's still required for every other type). | User-Guide §6 Applications; CSV input reference |
| 2026-10-06 | List Application Authentication Methods now has `Subject`, `Issuer` and `SubjectAlternativeName` columns (filled for `certificateattr` methods, blank otherwise), and the Delete Application Authentication Method picker shows those values instead of a blank Value. | User-Guide §6 Applications |
| 2026-10-06 | Not a code change: Test API strips `/PasswordVault` from the base URL, so PVWA paths must include it (for example `/PasswordVault/WebServices/PIMServices.svc/...`). Without it you get a 404. | User-Guide §9 Test API |
| 2026-10-06 | Generate Template for Add Application Authentication Method now writes an example `certificateattr` row under the header. Like the Add Safe From Template example, delete it before running the CSV. | User-Guide CSV templates |
| 2026-10-09 | Accounts CSV actions (all but Add and List) take optional `AccountID`, `AccountName`, `UserName` and `Safe` columns, and an `ObjectName` column is read as `AccountName`. AccountID alone is enough; otherwise give AccountName and/or UserName with Safe. AccountName now matches only the object name, not the username (CSVs that put a username there need a `UserName` column instead), and a name that matches more than one account fails the row instead of using the first match. Update has no UserName identifier because its UserName column is the new value. | User-Guide §4 Running an Action (CSV); §6 Accounts; Features |
| 2026-10-09 | The end-of-run log summary and each action's result now name the action that ran. Before, they could show another module's name (often "List Users"), for example in WhatIf runs and Export All. | User-Guide logging / reading the log file |
| 2026-10-09 | Add Safe From Template: each additional member now asks for SearchIn (Vault or an LDAP directory), like Add Safe Member From Template Role. In CSV, `ExtraMembers` entries take an optional 4th part: `Type:Name:RoleName:SearchIn`. The template safe's CPM is no longer copied as a member when it is in the CPM list, which fixes the error when you pick the same CPM. | User-Guide Safes / Add Safe From Template; CSV input reference |
