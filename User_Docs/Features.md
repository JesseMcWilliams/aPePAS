# aPePAS: Features

The full feature list. For how to use each feature, see the [User Guide](User-Guide.md). For CSV columns, see the [CSV Reference](CSV-Reference.md).

- **Two environments, one tool**: CyberArk Self-Hosted PVWA (v12+) and Privilege Cloud (ISPSS), with 68 actions across 10 categories: Accounts, Applications, Custom, Groups, Platforms, Policies, Reports, SafeMembers, Safes and Users. Only the actions your system supports are shown.
- **Authentication methods**: CyberArk, LDAP, RADIUS, SAML, OIDC, Shared, PKI and PKIPN on Self-Hosted; ClientCredentials, Interactive and SSO on Privilege Cloud. SAML, OIDC and SSO sign in through a WebView2 window.
- **Profiles**: named settings for each environment, stored per Windows user. Settings are plain JSON. The saved session token and the optional stored automation credential are DPAPI-protected. One profile can be the default.
- **Profile backup and restore**: back up selected profiles (settings and saved token) to a `.zip` with `[K]`, restore with `[X]`. A token restored to a different Windows user or machine can't be decrypted, and aPePAS tells you which profiles need a fresh login.
- **Startup options**: `-StartProfile` preselects a profile. `-AutoConnect` connects to it straight away, falling back to the profile list on any failure.
- **Automation mode**: `-StartProfile`, `-Category` and `-Action` run one action with no menus or prompts, with input from `-InputFile` (CSV) or `-InputJson`. `-OutputFolder` and `-FilenameFormat` control where and how CSV files are saved. Exit codes: 0 success, 1 crash or invalid parameters, 2 some items failed, 3 couldn't run.
- **Unattended runs with a credential store**: `Invoke-AutomationWithCredential.ps1` gets the profile's credential through aPeSecrets (CyberArk CP, CCP or Conjur, a DPAPI credential file, or Windows Credential Manager) and runs one automation action with it in memory. It can log in fresh with no saved session (Self-Hosted CyberArk/LDAP/RADIUS; Privilege Cloud ClientCredentials, and Interactive without MFA). `-ResolveOnly` tests the setup. `Sync-AutomationCredential.ps1` can instead store a credential as the profile's `.autocred` refresh fallback.
- **Session handling**: saved tokens older than 15 minutes are refreshed at login. Privilege Cloud ClientCredentials tokens are refreshed silently before they expire. Self-Hosted sessions are kept alive while you work. Other methods prompt you to log in again. A changed Base URL forces a fresh login. Sessions end after 10 minutes of inactivity.
- **CSV batch processing**: every write action, and some Get actions, accept one or more CSV files. Each file gets a results file (input columns plus `IsSuccess` and `Summary`).
- **CSV templates**: generate a CSV with the right header for any CSV action, with an example row where the action defines one.
- **Flexible account lookup**: Accounts CSV actions find an account by `AccountID`, or by `AccountName` (object name; `ObjectName` also works) and/or `UserName` within a `Safe`. A row that matches no account or more than one fails instead of guessing.
- **Search and pick lists**: accounts, platforms, groups, users and applications can be found by search and picked from a numbered list.
- **List drill-down**: from a List result, enter a row number to open that item's Get view, filled in from the row.
- **Safe member permission presets**: `ReadOnlyStrict`, `EndUser`, `PowerUser` and `SafeManager`, or set each permission individually (on Update, blank permissions and expiration keep the current values). `ReadOnlyStrict` never grants password retrieval, unlike PVWA's own `ReadOnly` role.
- **Template-based safes and members**: create a safe from a template safe's settings and members, and grant permissions copied from a template safe's role members, with a SearchIn picker for directory members.
- **Application authentication methods**: path, hash, OS user, machine address, certificate serial number, and certificate attributes (`certificateattr`, with `Subject`, `Issuer` and `SubjectAlternativeName` lists).
- **CPM picker**: every "pick a CPM" prompt lists CPM users from the vault, falling back to the profile's CPM List when that query fails or finds none.
- **WhatIf mode**: a dry run for the whole session, from `-WhatIf` or a profile's WhatIf Default. Every write request is logged and skipped.
- **Report download**: Export Report saves a generated PVWA report as Excel or CSV (Self-Hosted, PVWA 14.6+).
- **Bulk exports**: Export All (every List action, one CSV each), Export Entitlements, Export Local Group Members, Export LDAP Group Members (expanded through Active Directory) and Export Platform Details (one row per active platform with every policy setting).
- **Interactive API tester**: send raw GET, POST, PUT, PATCH or DELETE requests, view headers, and save the session to JSON.
- **Connectivity testing**: DNS, TCP ports and a Windows (SMB) or Linux (SSH) credential check against a server, one at a time or from CSV, with the password looked up in the vault if you don't give one. Extra ports can be checked for information.
- **Logging**: one log level for console and file (`-LogLevel`). Each session writes its own timestamped log file, and session logs older than 30 days are deleted at session start. Request bodies and error responses go to the file only, at DEBUG, with secrets masked.
- **Page Size and Display Limit**: Page Size sets records per API request (all results are always fetched). Display Limit shortens on-screen tables for List actions and Custom output tools (default 20). CSV files always get every row.
