# aPePAS CSV Reference

This page lists the columns for every action that accepts a CSV file (the actions tagged `[CSV]` on the action menu). For how to run a CSV file, see [Running an Action](User-Guide.md#4-running-an-action) in the User Guide.

## General rules

- The first row is the header. Each later row is one item, processed in order.
- **Required** columns must be in the header, spelled exactly as shown (including upper and lower case). A file that's missing one is skipped with a message, and nothing in it runs.
- Optional columns can be left out of the header or left blank in a row.
- Columns the action doesn't use are ignored, but they're copied into the results file. A filled-in column whose name contains `password` or `secret` is written to the results file as `***`.
- Each run writes a results file named `<input name>_<yyyy-MM-dd>_output.csv`: every input column plus `IsSuccess` and `Summary` (`OK`, or the first error). It goes to the profile's Output Folder if that folder exists (in automation mode, to `-OutputFolder` when given), otherwise next to the input file.
- **Generate Template** (`[3]` on the CSV menu) writes the header row for the action. Where the action defines example values, it also writes one example row. Delete that row before you run the file.
- Where a column says true/false, use `true` or `false` unless the notes say otherwise.

## Accounts

### Identifying the account

Every Accounts action that accepts CSV, except Add, finds the account with these optional columns. Give `AccountID`, or give `Safe` with `AccountName` and/or `UserName`.

| Column | Notes |
|---|---|
| `AccountID` | The account's ID. When it's filled in, the other identifier columns are ignored. |
| `AccountName` | The account's object name (the Name shown in PVWA), not its username. A column headed `ObjectName` works too. Needs `Safe`. |
| `UserName` | The account's username. Needs `Safe`. With `AccountName`, the account must match both. |
| `Safe` | The safe that holds the account. Required unless `AccountID` is filled in. |

If a row matches no account, or more than one, that row fails and nothing changes. In **Update**, `UserName` is the new username to set, so Update finds the account by `AccountID`, or by `AccountName` with `Safe`.

These actions use only the identifier columns: **Cancel CPM Task, Check In, Delete, Get, Get Activity, Reconcile, Request JIT Access, Resume Auto Management, Revoke JIT Access, Unlock, Verify**.

| Column | Used by | Notes |

## SafeMembers

### Permission columns (Add and Update)

`PermissionRole` takes a preset, or is left blank (or set to `Specified`) to use the permission columns:

| Preset | Grants |
|---|---|
| `ReadOnlyStrict` | List accounts, view audit log, view safe members. **No** password retrieval. |
| `EndUser` | Use, retrieve and list accounts. |
| `PowerUser` | EndUser, plus add, update content and properties, rename, delete and unlock accounts. |
| `SafeManager` | PowerUser, plus initiate CPM operations, manage safe, manage safe members, back up safe, view audit log, view safe members, create and delete folders, move accounts and folders. |
| blank or `Specified` | The permission columns below. |

The permission columns are `UseAccounts`, `RetrieveAccounts`, `ListAccounts`, `AddAccounts`, `UpdateAccountContent`, `UpdateAccountProperties`, `InitiateCPMAccountManagementOperations`, `SpecifyNextAccountContent`, `RenameAccounts`, `DeleteAccounts`, `UnlockAccounts`, `ManageSafe`, `ManageSafeMembers`, `BackupSafe`, `ViewAuditLog`, `ViewSafeMembers`, `AccessWithoutConfirmation`, `CreateFolders`, `DeleteFolders`, `MoveAccountsAndFolders`, `RequestsAuthorizationLevel1` and `RequestsAuthorizationLevel2`. `true`, `yes`, `y` or `1` means granted. Any other non-blank value means not granted. The two `RequestsAuthorizationLevel` columns can't both be true.

Rules for each row:

- **`PermissionRole` set:** the preset sets every permission, and the permission columns are ignored. An unrecognized role name means `ReadOnlyStrict`.
- **`PermissionRole` blank (or `Specified`):** the permission columns are used. A blank cell means `false` on Add, and keeps the member's current value on Update.
- **Everything blank:** Add fails the row, so a member is never added with no permissions. Update keeps the current permissions, so a row can change only the expiration date.

A generated template has every permission column, and that's fine: blank cells follow the rules above.

## Safes

### Add Safe

| Column | Required | Notes |
|---|---|---|
| `SafeName` | Yes | 1 to 28 characters, no leading space, none of `\ / : * < > " . \|`. |
| `Description` | No | |
| `Location` | No | Default: `\`. Only settable through CSV. |
| `ManagingCPM` | No | CPM user that manages the safe. |
| `NumberOfVersionsRetention` | No | Password versions to keep. Default: 5. |
| `NumberOfDaysRetention` | No | Days to keep. When it's greater than 0, it's used instead of `NumberOfVersionsRetention`. |
| `AutoPurgeEnabled` | No | `true`, `yes`, `y` or `1` (any case) turns auto-purge on. Anything else leaves it off. It can't be changed after the safe is created. |

### Add Safe From Template

Creates a safe from the profile's Role Template Safe: its settings and its members, except role groups (Role Group Prefix) and the template's own CPM when that CPM is in the CPM list.

| Column | Required | Notes |
|---|---|---|
| `SafeName` | Yes | Up to 28 characters. |
| `Description` | No | Never copied from the template. |
| `ManagingCPM` | No | CPM for the new safe. Blank means no CPM. The template's CPM isn't copied. |
| `ExtraMembers` | No | Extra members, in the format below. |

**`ExtraMembers` format:** entries separated by semicolons, each `Type:Name:RoleName[:SearchIn]`.

- `Type` is `User` or `Group`.
- `RoleName` must exactly match a role member on the template safe. Its permissions are copied.
- `SearchIn` is optional: `Vault`, or a directory ID. Leave it off to use the CyberArk default.

Example: `User:jdoe:Role_Viewer:Vault;Group:AppAdmins:Role_Admin:example.com`. The generated template includes an example row. Delete it before you run the file.

## Users

### Identifying the user

Every Users write action except Add finds the user with these optional columns. Give one of them.

| Column | Notes |
|---|---|
| `UserID` | Numeric user ID (from List Users). When it's filled in, `Username` is ignored. |
| `Username` | The exact username. If it matches no user, or more than one, that row fails and nothing changes. |

These actions use only the identifier columns: **Delete User, Disable User, Enable User, Unblock User**.

Passwords in a CSV file are in clear text. They're never logged and the results file shows `***`, but protect the input file and delete it after the run.
